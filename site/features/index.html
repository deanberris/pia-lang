      • 53. Protocols and deadlock are checked in Z3, as transition systems proved by constrained Horn clauses; explicit search stays for atomics, and TLA+ is an export format
      • 54. GIF and inflate are proved total on every input, decode to a written specification, and GIF round-trips exactly
      • 55. Sediment transport is integer mass moved downhill in height order, with conservation proved exactly

      • 58. Spec buffers: spec-only arrays that code writes, contracts read and codegen erases
      • 59. Digits group with ' or _; min t and max t are an integer type's bounds, folded to literals
      • 60. spread v0: iterations own the cells they write, proved one iteration at a time; MLIR's async runtime runs them
      • 61. Lean proves the facts Z3 cannot: lemmas and theory models are proved in Lean against statements piac generates, recorded in certificates by statement hash, and checked outside the edit loop; cost bounds are proved by Z3, and their asymptotics in Lean
      • 62. Cost bounds are contracts: costs c <= e bounds what a function spends on a named counter, tracked by a spec-only spent c and proved by Z3
      • 63. Opaque spec functions: a spec function marked @opaque keeps its definition out of every goal until a proof reveals it
      • 64. type always makes a new type: let length = type u32 is distinct from u32, converts only by applying a type to a value, and inherits only what it derives
      • 65. Pia code extends the compiler's lowering: @lower gives a function an MLIR form and a type an MLIR type, the Pia definition stays the specification, and each lowering is proved to refine it or is listed as trusted
      • 66. Nonlinear goals are tried first with Z3's int-blasting solver, and other solvers are kept out of the pipeline for now
      • 67. Release 0.1.0 is a small Llama-architecture LLM ported from PyTorch to Pia, proved where a proof means something, running inference on an M3 Mac on CPU SIMD and on the GPU through linalg
      • 68. GPU compute: a proved spread placed on the GPU, lowered through SPIR-V and SPIRV-Cross to Metal, launched by a small trusted shim
      • 69. Pure and impure functions: computed purity, @pure assertions, and @impure interface boundaries
      • 70. Raw binary embedding: @embed for compile-time fixed byte blobs, hermetic roots, opaque verification and direct LLVM emission
      • 71. Function references: a function is a value that travels by reference
      • 72. A drop never grows the stack: every drop is one walk, proved against the recursive drop, with a fixed stack bound per type
      • 73. Certificates record who proved a module and with what, advisories revoke trust in faulty provers, and every breaking change ships a migration
      • 74. Library types: a type written in Pia gets an MLIR type, ops and proofs from its library, and Pia.Tensor over MLIR tensor is the proof point
      • 75. Codegen is benchmarked against C, C++, Rust and Zig on public problems, same algorithm first, counted in instructions on Linux and timed on Apple Silicon
      • 76. Transparent exports: an importer proves against an exported function's body, as a caller in its own module does
      • 77. A definition that states no contract takes the contract of the interface that lists it
      • 78. Library functions lower to pia_lib.call, a Pia-owned op whose meaning is its Pia body, and a late pass either expands it into the body or substitutes an upstream op through a rule proved against the body
      • 79. Pia IR: a versioned op schema Pia controls, in lock-step with piac, with deprecations and migrations
      • 80. Protocol Buffers in Pia: a metaprogram that turns .proto into proved types and codecs, and Pia IR as a protobuf schema

    Feature index¶

    Every feature piac builds today, with the page that explains it and a working example: a file in tests/verify that bazel test //tests/verify:<name>_test proves, and whose expected report sits in its comments. To see a feature at work, read its example, or run piac --verify on it. Status says what is built and what comes next; the standard library lists the modules written with these features.

    tools/docs/check.py fails a pull request that adds a feature test without a line here.
