# Status and roadmap

Pia is an experimental language under active development. The compiler proves and compiles a growing part of the language, and the rest is designed but not built. [The feature index](features.md) lists every built feature with a proved example, and [the standard library](library.md) every module written with them. Nothing is stable yet: syntax, flags and the compiled ABI can all change before a 0.1 release.

## Known limitations

- **Loops need invariants.** After a loop, only its invariant is known, so a goal after the loop that depends on what it did needs an invariant that says so.
- **Termination is checked for loops and direct recursion only.** A `while` loop or a recursive call without `decreases` is a skipped goal, which `piac` refuses unless `--allow-unproved` accepts it. Mutual recursion is not checked.
- **Calls inside contracts** to functions other than spec functions and pure functions of scalars are unknown values, so a contract cannot rely on what such a function computes.
- **Counterexamples do not show array contents** yet, only lengths and scalar values.
- **Function values are partly compiled.** Typed lambdas without captures, and top-level functions, can be passed to a parameter of function type, which may carry a contract, and a lambda can be bound by a `let` and applied ([ADR 0044](adr/0044-function-values-and-lambdas.md), steps 1 and 2). So can function objects, any record or variant with an `apply`, which `g x` calls. `Function` is a standard concept, and an overload set may mix functions that take values with functions that take functions. Lambdas list their captures, each copied, borrowed or referenced (`inout`), with loans checked to the lambda's last use (step 3). Untyped lambdas take their parameter types from where they are passed, and a `let` of an untyped or explicitly generic lambda is generic (step 4). Each call with a function argument is proved and compiled as its own specialisation. Partial application (`add 1`), functions as results (`: u8 -> u8`) and moved captures work too (step 7). A `let` of a function type holds a reference to a top-level function, proved against the arrow's contract once, with calls through it seeing only that contract ([ADR 0071](adr/0071-function-references.md), step 1). Generic lambdas that capture, rebindable references and functions stored in data come later.
- **Floats are bit patterns to the prover** with exact IEEE order, until ADR 0038's real-valued encoding lands: a goal that needs what `+` or `*` computes fails rather than being proved ([verifier.md](verifier.md#floats)).
- **Not compiled yet:** functions stored in data and generic lambdas that capture, `dyn`, `vec<T, k>`, refinement types and `where` on values, nested modules, and the concurrency runtime beyond `spread`. `piac` reports these as "not supported yet" at their source location.
- **Two targets, one GPU.** Code generation targets arm64 macOS and x86_64 Linux; `@place(gpu)` runs only on Apple GPUs, through Metal.

## Roadmap

The plan is a sequence of milestones, each a GitHub issue, building towards the flagship demo: stream delineation and sediment transport over a terrain heightmap, proved correct and running across the CPU and GPU ([ADR 0016](adr/0016-stream-delineation-flagship-demo.md)).

| Milestone | Scope | |
| --- | --- | --- |
| M0 to M7 | Bazel build, grammar, parser, MLIR dialects, IRGen, verifier, arm64 codegen, records and the metaprogram engine | done |
| [M8](https://github.com/deanberris/pia-lang/issues/9) | Modules, explicit interface imports, proof certificates and a link check | next |
| [M9](https://github.com/deanberris/pia-lang/issues/10) | Generic types, concepts with laws, adapters and call-site deduction | generic types and functions, overloading, concepts, the definition check, adapters, ranking by constraints and choosing by preconditions done (ADR 0034 complete); generic bodies proved once over their type parameters as well as at each instance (ADR 0043, step 1 of 5); ADR 0035: type-level metaprograms in types and `where` predicates, their totality check, and soft failure with `--explain-overloads` done (ADR 0035 complete) |
| [M10](https://github.com/deanberris/pia-lang/issues/11) | Vectorisation driven by proved facts, and `vec<T, k>` | |
| [M11](https://github.com/deanberris/pia-lang/issues/12) | Floats: strict IEEE, and three ways to allow reassociation | `f32` and `f64`: literals, `+ - * /`, negation, IEEE comparisons, conversions to and from integers and between widths, `to_bits`/`from_bits`, buffers and record fields of floats, C calls, strict codegen (no FMA contraction, subnormals kept); proofs see floats as bit patterns, with exact IEEE order and uninterpreted arithmetic until ADR 0038's encoding |
| [M12](https://github.com/deanberris/pia-lang/issues/13) | Concurrency: `spread`, collectives, and compile-time checks that collectives match | `spread` v0 done, on the CPU and, with `@place(gpu)`, on the GPU; collectives next |
| [M13](https://github.com/deanberris/pia-lang/issues/14) | PNG and GIF decoding and encoding, written in Pia | GIF decoding and animated encoding, deflate and zlib done ([ADR 0054](adr/0054-proved-gif-and-inflate-codecs.md)); PNG next |
| [M14](https://github.com/deanberris/pia-lang/issues/15) | The stream delineation demo | delineation [done](streams.pia.md), [sediment transport](sediment.pia.md) done, its GIF animation written by Pia's own encoder |
| [0.1.0](adr/0067-release-0-1-0-a-proved-small-llm.md) | The first release: a small LLM, llama2.c's TinyStories, ported to Pia, proved, and running on Apple silicon with its matrix products on the GPU | the tokenizer and the safetensors reader done; floats, the model and GPU matmuls next |

Alongside these, a Presburger stage will decide affine goals such as aliasing and loop-carried dependence ([ADR 0020](adr/0020-presburger-for-affine-goals.md)). After a 0.1 release, Pia will be offered to [Compiler Explorer](https://github.com/deanberris/pia-lang/issues/30).
